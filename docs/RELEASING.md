# 独立发行流程

此仓库只接收经过审核的源码快照，不合并其他仓库的 Git 历史，不共享远程、分支或发布记录。下载和更新地址由 `packaging/Info.plist` 的 `QishengUpdateRepository` 指定。

## 同步源码

1. 在开发仓库选定并提交本次要发行的代码，保持工作区干净。
2. 在本仓库运行 `python3 scripts/stage_release_source.py --source "$SOURCE_REPOSITORY" --output .incoming/candidate`。工具只导出允许的源码与参考资源，不执行对方的脚本，不复制 Git、配置、钥匙串、录像或私人夹具。它不会修改本仓库现有文件或提交。
3. 检查候选目录与本仓库的差异，再引入本次需要的功能。更新程序、发行配置、README、CI、隐私检查和本仓库测试必须单独复核，不能整目录覆盖。本仓库的版本号和更新仓库不得退回开发仓库的值。
4. 本仓库独立写提交，使用 GitHub noreply 邮箱。私人来源信息、测试截图和详细对局记录不写进提交、发布说明或 CI 日志。

## 发布检查

日常提交与标签只执行构建、测试和打包，不为每次提交上传大附件。需要下载 CI 测试包时，在 Actions 手动运行工作流并勾选 `upload_packages`；需要账号有可用的 Actions 存储额度。上传失败会明确报错，不视为已发布。它只上传 ad-hoc 测试产物，不创建 GitHub Release，不能替代稳定签名的正式安装包。本地安装包始终可以通过下面的打包脚本生成。

- 运行源码树与全部提交历史隐私扫描；人工检查所有新图片与二进制文件。正则扫描不能证明没有任何隐私。
- 运行核心检查、worker 测试及完整应用构建。明确区分公开合成测试、可选私人回归和真实游戏测试，不能用前两者替代后者。
- 在一台已授权的 Mac 上检查录屏边界、声音、整批切换、停止保存、己方/对方视角，以及应用内更新。不得为测试重置用户的系统权限。
- `bash scripts/package_release.sh` 生成 ZIP、DMG 和摘要。检查打包清单、图片元数据、原生可执行文件及冻结 Python 模块；不从个人 Applications 目录复制旧应用来当发行产物。
- 签名身份必须明确指定；默认 ad-hoc 包仅供开发验证。使用私人签名证书时，只在受控机器或受保护的签名任务中使用，不将证书、私钥、钥匙串或密码提交到仓库。
- 上传安装包前核对版本、签名和 SHA-256。GitHub Release 的附件摘要必须可用，更新程序才会接收；证书签名的旧安装仍要求新版满足原签名身份。新仓库本身不会改变旧应用的更新入口。
- 只有真实验收完成的版本才作为正式版。未完成的候选包保留为构建产物或明确的预发布，不把它提供给正式自动更新。

## 当前候选的边界

- 1.6.0 保留原生录屏、角色识别复核、角色库、Safari 启动、保活和双轮录制。
- 掷骰后预先暂停、切换视角、再恢复的改动需要候选版实机复测。部分窗口下自动二倍速可能不生效，必须检查成片速度，不能宣传为所有环境都已通过。
- 双视角合成脚本仍需人工核对多点时间对应关系，没有自动同步或应用内后台合并。没有录到的开局信息不能补造。
- 同一仓库的全部分支、提交、附件及 Issues 都属于公开范围。改公开之前重新检查整个仓库，而不是只看默认分支。
