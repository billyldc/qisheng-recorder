# 双视角合成原型

目前是开发中的离线脚本，尚未接入应用的自动录制。它不会自动判断两段录像是否同步，也不能补出切换视角前没有录到的手牌。请勿把导出成功视为同步准确。

成片保持原来的画面比例和牌桌大小：顶部的对方牌背原地换成正向手牌，右侧原有窄栏分成上方对方骰子、下方己方骰子。底部己方手牌不动，不额外加宽画布或添加大块边栏。只使用己方音轨，原文件不修改。需安装 FFmpeg，脚本本身仅使用 Python 标准库。

## 使用步骤

1. 用 `scripts/merge_dual_view.py prepare` 指定 `--own`、`--opponent` 两个视频，`--own-metadata`、`--opponent-metadata` 两份录制 JSON，以及新的 `--output` 计划文件。
2. 核对日期、模式、阵容及实际上下视角。在计划中填写两段视频的游戏区域 `viewport`，以及相对于对方游戏区域的 `opponentHand`、`opponentDice`，相对于己方游戏区域的 `ownDice`。再填写 `composition` 中这三个区域的目标位置，目标坐标相对于己方游戏区域。裁框均为左上角坐标 `[x, y, width, height]`，范围 0–1，不预设屏幕尺寸或自动裁黑边。顶部手牌需覆盖原有牌背，两组骰子需位于同一右侧窄栏且互不重叠；旧计划需补充并重新核对这些位置，不会自动沿用旧的扩展画布布局。
3. 在 `anchors` 填写至少四个同一牌桌事件的时间：`own`、`opponent` 以源文件秒数为单位，`event` 写事件说明。每对相邻事件之间，再用一个不同事件填写 `checks`，验证中间没有暂停、卡顿或速度变化。每段最长 30 秒；遇到变化需缩短或另选片段，不能硬拉整段时间。
4. 确认裁框、同局以及所选时间范围内双方视角始终正确，再将 `confirmed` 中四项设为 `true`，`status` 改为 `reviewed`。
5. 运行 `python3 scripts/merge_dual_view.py render --plan <计划.json> --output <新的合成.mp4>`。输出旁附 `.merge.json`，记录输入摘要、同步点、截取范围及舍弃的开头/结尾。

尚未完成时间核对时，可把 `render` 换成 `preview` 检查排版，最长 30 秒。它仍要求确认同局、实际视角及裁框，但允许没有独立时间检查点，并强制在视频中保留“布局预览 · 同步待核对”标记；不能当作验收成片。

微调手牌与骰子高度时，可以多截取手牌上方一点背景，使手牌下移但仍盖住原牌背。若右侧裁片边缘与上方骰子相接，仅在人工确认重叠处没有卡牌后，才可在 `composition` 中设 `rightEdgeBackgroundOverlap: true`；允许覆盖的右边背景宽度最多占画面 2%，默认仍拒绝重叠。

先导出短片逐帧检查技能、扣血、换人、手牌与骰子，再扩大范围。脚本按多个同步点分段调整对方视频速度，拒绝不一致的独立检查点；它不自动证明填写的检查点是真实事件。不把未经检查的部分标成“全局已同步”，不覆盖旧成片。

后续工作：自动寻找同步候选、独立画面核验、缺失片段提示，以及录完后的后台合成队列。真实双轮录制、不同窗口比例和暂停/变速用例通过前，不启用应用内自动合并。
